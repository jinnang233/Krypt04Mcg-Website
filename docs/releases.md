### 客户端 0.27.5

- 聊天分片从首次接收起计算固定期限，新索引不能续期；缓存满时拒绝新消息 ID，保留在途组装。畸形 ID、索引、总数和 Base64URL 提前拒绝。
- 群组、已发送缓存和解密/旧交换重放历史拒绝符号链接并收紧权限；群组和已发送缓存采用私有临时文件替换。
- 内置文件接收必须在接纳后两分钟内收到完整内容与认证 EOF，否则取消并释放共享工作线程。普通流 API 的 60 秒空闲超时保持原有行为。
- 补齐每种受支持后量子签名参数的 `+Ed25519` / `+Ed448` 选项。两份签名都必须有效，自定义混合格式仍属实验性设计，BC 原生默认组合保持原有行为。

### 中继插件 1.8.2

普通聊天/私信命令的待处理片段缓存满时，忽略新消息 ID，避免驱逐在途消息。完成、超时、断线或重载释放容量。自定义载荷、原始流 API 和文件转发不使用这个收集器，转发格式与吞吐行为保持原样。

### 反向转发 1.3.2

- 待处理邀请最多 64 个、每玩家四个，期限固定两分钟。重复邀请不能替换首次展示的玩家或目标端口，也不能续期。
- 无关或重复撤销不再触发同步写盘；授权文件拒绝链接、限制到所有者权限，保存使用随机临时文件。
- 控制消息与隧道授权头共用 64 个待处理名额，每玩家最多 16 个，期限固定 30 秒。到期关闭读取，晚到消息不能执行控制动作或连接本地端口。
- 断开连接会关闭待处理读取并取消排队控制回调。已经建立的隧道保持每路由八条连接及正常半关闭/撤销逻辑，不受这项 30 秒总期限限制。

### 升级注意事项

这轮安全修复没有更改网络协议、公开流 API、JSON 或授权文件格式。反向转发最低核心版本仍是 0.23.0，建议搭配客户端 0.27.5 与中继 1.8.2 获得各组件的修复。

此前把群组、缓存、历史或 `routes.dat` 放在符号链接路径下的用户，需要备份后迁移到普通本地目录；备份保留原始账号主密钥。慢速文件和握手可能到期，超出配额的连接突发可能被关闭，需重试。采用新长期签名选择时，应重新生成密钥、重新交换公钥并核对指纹，双方须支持所选标识。

这些是针对性审查和回归修复。实际游戏联机、Windows 权限、全部高成本后量子参数和既有 GitHub 依赖告警仍有未验证或未解决部分，详见[安全与限制](./reference/security.md)。
