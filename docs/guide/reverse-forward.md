# 反向 TCP 转发

K04M Reverse Forward 1.3.2 使用 Krypt04Mcg 的加密流，把一名玩家本机的 TCP 入口接到另一名玩家明确授权的本地服务。监听端和目标端均限定为 IPv4 `127.0.0.1`，不会自动启动目标服务。

## 安装与要求

- 两端安装匹配加载器的扩展和核心模组，目标为 Minecraft 26.3、Java 25。核心最低 0.23.0，建议使用 0.28.0 获得最新的独立安全修复。
- 两端开启核心 `enableDataApi`，交换公钥，并通过可信渠道核对完整指纹。
- 服务端中继必须支持 `krypt04mcg_stream:control` 和配置范围内的 `krypt04mcg_stream:data/<slot>`，建议使用插件 1.8.3。控制与隧道流共同消耗核心通道池，默认 16 个槽位。

发布入口见[下载与构建](../downloads.md)。扩展仍属实验性软件，不适合敏感或生产流量。

## 示例：Alice 访问 Bob 的本地网页服务

先由 Bob 自行启动监听 `127.0.0.1:8080` 的服务。Alice 执行：

```text
/k04mrf register web 25570 8080
/k04mrf invite web Bob
```

Bob 检查邀请中显示的玩家、路由和本地目标端口后，使用实际显示的邀请 ID 接受：

```text
/k04mrf accept <invitationId> 8080
```

Alice 收到接受后，本机 `127.0.0.1:25570` 的连接会被转发到 Bob 的 `127.0.0.1:8080`。授权绑定玩家身份与路由 UUID，Bob 可以在接受时选择另一个目标端口。

## 查看、停用与撤销

| 命令 | 用途 |
| --- | --- |
| `/k04mrf invitations` | 查看待处理邀请 |
| `/k04mrf deny <invitationId>` | 拒绝邀请 |
| `/k04mrf list` | 查看路由、授权与实际监听状态 |
| `/k04mrf stop <name>` | 关闭入口及活动连接，保留授权 |
| `/k04mrf start <name>` | 重新开启已授权入口 |
| `/k04mrf remove <name>` | 删除发起方路由并通知对方撤销 |
| `/k04mrf revoke <routeId>` | 撤销授权并关闭活动连接 |

ID 可以使用列表中显示的八字符前缀；有歧义时拒绝命令。端口被占用时不会监听，释放端口后可用 `start` 重试。

## 期限、容量与存储

待处理邀请从首次接收起保留两分钟，最多 64 个、每玩家四个；重复消息不能替换邀请内容或续期。控制消息和隧道授权头最多同时处理 64 个、每玩家 16 个，并须在接纳后 30 秒内完成。更小的核心 API 通道池仍限制可用槽位。分段进展不能续期，超额或到期请求关闭后需重试。

已建立隧道每路由最多八条连接，支持 TCP 双向半关闭，不受元数据的 30 秒总期限限制。断开连接会取消待处理读取、排队控制动作、监听器和活动连接；重新连接后，已接受且启用的路由可恢复监听。

路由与授权保存于 `config/k04m-reverse-forward/routes.dat`，待处理邀请不写盘。目录与文件仅允许本地所有者访问，POSIX 权限为 `700` / `600`；保存使用随机私有临时文件。文件和父目录中的符号链接、悬空链接被拒绝，原先使用链接存储时需备份并迁移到普通本地目录。
